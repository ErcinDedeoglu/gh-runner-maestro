# AGENTS.md — gh-runner-maestro

Python orchestrator that launches and monitors multiple `gh-runner` containers defined by a JSON matrix env var. Ships as a single Docker image. No test suite, no linter config.

## Layout

- `src/main.py` — `MaestroService` main loop: validate config → pre-pull images → launch runners → monitor every 30s → `docker system prune -a -f --volumes` when *all* managed runners are idle.
- `src/config.py` — parses `RUNNERS_MATRIX` JSON or legacy single-runner env vars into validated dicts. Accepts legacy keys `repo_url`/`runner_count` and normalizes them to `url`/`count`. Token resolution order: entry `token` → `DEFAULT_RUNNER_TOKEN` → `GITHUB_PAT`.
- `src/docker_runner.py` — `RunnerManager`. **Does not use the Docker SDK to create containers.** It shells out to `docker run --rm …` via `subprocess.Popen` and tracks PIDs in `self.runner_processes`. The Docker SDK path in `list_runner_containers` / `cleanup_containers` filters on labels `maestro.managed=true` and `maestro.target_url=<url>` that the current `start_runner` never sets — so that branch is effectively dead code for runners created by this process. Keep this in mind before "fixing" it.
- `src/entrypoint.sh` — PID 1. Starts an internal `dockerd` (with an explicit `/etc/docker/daemon.json` pinning `storage-driver: vfs`, `cgroupdriver=cgroupfs`) only if both `DOCKER_HOST` is unset *and* `/var/run/docker.sock` is missing. Then execs `python3 -u main.py` from `/venv`.
- `src/Dockerfile` — Ubuntu 24.04, Python deps installed into `/venv` (not system Python). Declares a non-root `maestro` user and a `HEALTHCHECK` that pings Docker, but the current `ENTRYPOINT` runs as root; the `maestro` user + `gosu` install are wired up but not invoked.
- `src/requirements.txt` — `docker>=7.0.0`, `python-dotenv>=1.0.0`, `pyyaml>=6.0`. `pyyaml` is declared but currently unused in `src/`.
- `src/health_check.py` — standalone CLI for health probes; not imported by `main.py`.

## Environment contract

- `RUNNERS_MATRIX` (JSON array) is the primary input. Per-entry keys: `url` (required), `count` (1–50), `labels` (string or list), `token`, `image` (default `dublok/gh-runner:latest`), `ephemeral` (default `true`), `disable_update` (default `true`). See `validate_runner_config` in `src/config.py` for the exact rules — tokens must start with `ghp_|gho_|ghu_|ghs_|ghr_` or a warning is logged. Validation is strict; an invalid entry aborts startup.
- Legacy single-runner fallback (when `RUNNERS_MATRIX` is unset): `RUNNER_URL`, `GITHUB_PAT`, `RUNNER_COUNT`, `RUNNER_LABELS`, `RUNNER_IMAGE`.
- `DOCKER_MODE` — override for how spawned runners get Docker: `host-socket`, `dind`, or `standalone`. **Default is `standalone`** (see `_detect_docker_mode` in `src/docker_runner.py`). The README's "auto-detects" wording is misleading; code is the source of truth. `standalone` mounts `/sys/fs/cgroup`; the other two mount the docker socket and set `DOCKER_HOST`/`SKIP_DOCKER_DAEMON=true` on the spawned runner.
- `LOG_LEVEL` (default `INFO`). Logs go to stdout and `/var/log/gh-runner-maestro/maestro.log` if that directory exists.

## Env contract it *emits* to the runner

`start_runner` sets `GITHUB_PAT`, `RUNNER_URL`, `RUNNER_NAME`, and conditionally `RUNNER_LABELS`, `RUNNER_EPHEMERAL=true`, `RUNNER_DISABLE_UPDATE=true`. These names must match `gh-runner/src/entrypoint.sh`.

## Build / run locally

```sh
docker build -t gh-runner-maestro:dev src
docker compose up --build   # uses docker-compose.yml with sample RUNNERS_MATRIX (placeholder tokens)
```

The committed `docker-compose.yml` has placeholder tokens like `YOUR_GITHUB_TOKEN_1`. It will fail validation until you either edit it or set `DEFAULT_RUNNER_TOKEN` and remove the placeholders — do not commit real tokens.

## Gotchas

- Never "clean up" the Docker-SDK label filters in `RunnerManager` without first making `start_runner` actually create labeled containers. Today they only guard against a feature that isn't implemented.
- `docker system prune -a -f --volumes` runs automatically when every managed runner exits. Don't run this image on a host with other important Docker workloads.
- `ephemeral: true` (default) means each runner container has `--rm` and exits after one job. Scale-down is a no-op (`main.py`'s "excess runners" branch just waits for natural termination); changing `count` downward won't kill anything.
- `privileged: true` is required in the compose file — the internal `dockerd` will not start without it when running in DinD mode.

## CI

`.github/workflows/build-and-push.yml` delegates to `dubloksoftware/workflows/.github/workflows/build-and-push.yml@main` with `context_path: src`. Only pushes touching `src/**` rebuild (plus nightly cron and manual dispatch). `.version_v1.0.json`, `.sbom/`, `.vulnerability_report.txt` are generated by that workflow — don't hand-edit.
